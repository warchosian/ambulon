    1. Authentification

    Comme à travers le site web du wiki SI, l’accès en lecture à la plupart des informations est possible sans authentification via l’API. L’authentification n’est nécessaire, pour la lecture, que quand on souhaite accéder à des informations protégées, réservées à la MOA, la MOE ou aux responsables SSI. Bien sûr, comme à travers le site web, elle est requise dans tous les cas pour effectuer des modifications (créations, mises-à-jour ou suppressions de ressources).

    L’authentification dans une requête est obtenue au moyen d’un jeton d’authentification à préciser dans l’entête HTTP. Ce jeton doit y être associé à la clé « X-Wikis-API-Key ». La déclaration à ajouter doit donc se présenter ainsi (avec votre propre jeton !) :

    X-Wikis-API-Key: wTyK49SXNjjbZGrJqBM9Ihac0tVL2yP5COVTYlbo

    Chacun peut générer un jeton d’authentification pour lui-même depuis sa page personnelle de l’annuaire des wikis.

    Pour atteindre votre page personnelle, faites une recherche de vos nom et prénom dans https://wikisi.e2.rie.gouv.fr/annuaire/recherche/ et cliquez sur le lien vers votre page dans le résultat de la recherche. Passez en mode « Modifications » en cliquant sur le petit crayon dans la barre d’outils fixe en bas à droite, puis, dans la section « Divers », dans le champ « Jeton d’authentification », sélectionnez « Créer un jeton d’authentification ». Validez la demande en cliquant sur le bouton « Valider les modifications ». Votre jeton d’authentification est alors disponible dans la section « Divers » de votre page, dans le champ « Jeton d’authentification ».

    2. Collection d’objets et pagination

    La réponse à une requête GET sur une collection d’objets (par exemple /wikisi/api/application/, /wikisi/api/donnee/) peut potentiellement être volumineuse et comprendre de nombreux objets. Afin dans tous les cas de proposer des temps de réponse raisonnables, l’API met en œuvre un mécanisme de pagination et retourne les résultats par tranches. Ainsi, quand la collection-résultat compte « trop » d’éléments, l’API n’en retourne donc qu’une partie : une page, sorte de fenêtre sur le résultat. Les pages sont caractérisées par deux paramètres:

    • offset: l’offset du premier objet de la page, c’est-à-dire sa position, comptée à partir de 0, dans la collection-résultat complète (la collection-résultat est donc une collection ordonnée). Si le paramètre offset n’est pas précisé dans la requête, la valeur par défaut 0 est prise en compte.
    • limit: le nombre maximum d’objets dans la page. Si le paramètre limit n’est pas précisé dans la requête, la valeur par défaut 25 est prise en compte. limit ne peut excéder 100.

    Ainsi, par exemple, sur une collection-résultat complète valant [a, b, c, d, e, f, g, h, i, j, k], une page définie par offset=3 et limit=5 contient [d, e, f, g, h].

    Exemples de requêtes:

    GET /wikisi/api/application/
    => demande les 25 premiers objets « Application » (offset=0 et limit=25)

    GET /wikisi/api/application/?limit=100
    => demande les 100 premiers objets « Application » (offset=0 et limit=100)

    GET /wikisi/api/application/?offset=30&limit=10
    => demande 10 objets « Application » à partir du 31ème (offset=30 et limit=10)

    Pour faciliter le traitement des pages demandées, les réponses aux requêtes GET sur les collections d’objets précisent les offset et limit des pages ainsi que total_count, le nombre total d’objets satisfaisant à la requête.

    Ainsi, par exemple:
    GET /wikisi/api/application/
    retourne:
    { "applications":[...], "total_count":1017, "offset":0, "limit":25 }

    3. Erreurs et avertissements

    L’exécution des requêtes est susceptible de générer des erreurs et/ou des avertissements.

    Les erreurs empêchent la bonne exécution des requêtes qui ne retournent alors pas de données ou n’effectuent pas les créations, mises à jour ou suppressions de ressources demandées. Supprimer la cause de ces erreurs est indispensable pour permettre leur bonne exécution.

    Les avertissements n’empêchent pas l’exécution des requêtes mais font état de difficultés rencontrées qui peuvent avoir altéré le résultat ou l’action demandée. Une analyse des messages d’avertissement est indispensable pour vérifier que les requêtes ont malgré tout effectué le travail qu’on attendait d’elles.

    En cas d’erreur(s), l’objet résultat de la requête comprend un champ errors, dont le contenu est un objet dont les champs regroupent les messages d’erreur :

    • par thématique quand les erreurs sont générales. Exemples de thématique : “paramètres”, “authentification”, “requête”, “objet à créer”, “serveur” ;
    • par ID d’objet si l’erreur est liée à l’objet ou l’un des objets traités.

    En cas d’avertissement(s), l’objet résultat de la requête comprend un champ warnings, dont le contenu est un objet similaire à celui contenu dans le champ errors.

    GET /wikisi/api/application/?limit=max

    4. Requêtes sur les objets « Application »
    4.1 Lecture des objets « Application »

    Les objets « Application » (schéma JSON) sont accessibles en lecture via l’URL /wikisi/api/application/. Les paramètres fields, sort, unite, offset, limit et les restrictions sur les champs permettent de sélectionner les objets, préciser les champs demandés, et définir l’ordre dans lequel ils (objets et champs) doivent être retournés.

    GET /wikisi/api/application/

    Demande une liste d’objets « Application ». Par défaut, sans paramètre précisé, tous les objets « Application » contenus dans la base de connaissance et tous leurs champs sont demandés (coûteux !).

    Paramètres

    Les paramètres et leurs valeurs sont transmis de façon standard dans l’URL : /wikisi/api/application/?param1=val1&param2=val2&...&paramN=valN :

    • fields = nom_champ1,...,nom_champN : liste des champs dont on demande la valeur (chaîne de caractères, noms séparés par des virgules).
      => L’ordre des champs choisi est celui utilisé dans le résultat pour présenter leurs valeurs.
    • sort = nom_champ1,...,nom_champN : liste des champs sur lesquels trier le résultat (chaîne de caractères, noms séparés par des virgules).
      => Sans paramètre sort précisé, les objets « Application » sont triés sur leur nom par ordre alphabétique (tri ascendant).
      => L’ordre descendant sur un champ est spécifié en faisant précéder le nom du champ du signe « – ».
    • unite = nom_de_structure : nom de structure d’une l’unité (chaîne de caractères).
      => Les objets « Application » retournés auront cette unité ou l’une de ses composantes comme acteur.
    • offset = valeur_offset : offset de la page (nombre entier, à partir de 0).
    • limit = valeur_limit : nombre d’objets maximum (souhaité) dans la page (nombre entier).
      => La valeur maximale de limit est 100. En cas de valeur spécifiée supérieure, la valeur 100 est retenue et un avertissement de thématique “paramètres” est généré.
    • {nom_de_champ} = valeur_du_champ : critère de sélection des objets demandés portant sur la valeur du champ {nom_de_champ}.
      => Les critères de sélection précisent les conditions que doivent vérifier les objets demandés. Autant de critères de sélection que nécessaire peuvent être cumulés au sein d’une même requête.
      => valeur_du_champ peut valoir l’une des valeurs spéciales $null ou $notNull. Ces valeurs spéciales permettent de sélectionner les objets pour lesquels le champ est vide, ou non.
      => valeur_du_champ peut être précédée d’une déclaration d’ opérateur de comparaison qui va alors se substituer à l’opérateur « égal à » utilisé par défaut. Les opérateurs de comparaison disponibles sont:
      • $eq_ci : « égal à » insensible à la casse. $eq_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $neq : « différent de ». $neq est utilisable avec les champs de tout type.
      • $neq_ci : « différent de » insensible à la casse. $neq_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $in : « inclus dans ». valeur_du_champ doit être une liste de valeurs séparées par des virgules. $in est utilisable avec les champs de tout type.
      • $in_ci : « inclus dans » insensible à la casse. valeur_du_champ doit être une liste de valeurs séparées par des virgules. $in_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $notIn : « non inclus dans ». valeur_du_champ doit être une liste de valeurs séparées par des virgules. $notIn est utilisable avec les champs de tout type.
      • $notIn_ci : « non inclus dans » insensible à la casse. valeur_du_champ doit être une liste de valeurs séparées par des virgules. $notIn_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $gt : « plus grand que ». $gt est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $gte : « plus grand ou égal à ». $gte est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $lt : « plus petit que ». $lt est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $lte : « plus petit ou égal à ». $lte est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $contains : « contient » (sensible à la casse). $contains est utilisable avec les champs de type Chaîne de caractères.
      • $contains_ci : « contient » insensible à la casse. $contains_ci est utilisable avec les champs de type Chaîne de caractères.
      • $startsWith : « commence par » (sensible à la casse). $startsWith est utilisable avec les champs de type Chaîne de caractères.
      • $startsWith_ci : « commence par » insensible à la casse. $startsWith_ci est utilisable avec les champs de type Chaîne de caractères.
      • $endsWith : « finit par » (sensible à la casse). $endsWith est utilisable avec les champs de type Chaîne de caractères.
      • $endsWith_ci : « finit par » insensible à la casse. $endsWith_ci est utilisable avec les champs de type Chaîne de caractères.
      • $regex : « Recherche par expression régulière » (sensible à la casse). La syntaxe d’expression régulière est celle de PostgreSQL. $regex est utilisable avec les champs de type Chaîne de caractères.
      • $regex_ci : « Recherche par expression régulière » insensible à la casse. La syntaxe d’expression régulière est celle de PostgreSQL. $regex_ci est utilisable avec les champs de type Chaîne de caractères.

    Résultat

    {

    "applications" : liste d’objets,
    => Objets « Application » satisfaisant à la requête (restreints aux champs demandés et à leurs valeurs).

    "total_count" : nombre entier,
    => Nombre total d’objets dans le résultat de la requête.

    "offset" : nombre entier,
    => Offset de la page.

    "limit" : nombre entier,
    => Nombre maximum d’objets dans la page.

    "errors" : objet,
    => Dictionnaire des erreurs générées lors du traitement de la requête, regroupées par thématique ou ID d’objet « Application ». Si ce champ est présent, les champs "applications", "total_count", "offset" et "limit" ne le sont pas.

    "warnings" : objet
    => Dictionnaire des avertissements générés lors du traitement de la requête, regroupés par thématique ou ID d’objet « Application ».

    }

    Utilisation des champs et méthodes des types « date » et « date-heure »

    La référence dans les paramètres fields et sort, et dans les critères de sélection, à des champs ou méthodes des types « date » et « date-heure » est possible en utilisant l’opérateur « . ».

    Exemples:

    • fields=creationFiche.date,modificationFiche.date : demande les dates (sans les heures) de création et de dernière modification des applications sélectionnées.
    • moe_entreePortefeuille.year=$lte 2023 : sélectionne les applications entrées dans le portefeuille MOE en 2023 et avant.

    Les champs et méthodes du type « date » disponibles sont :

    • year : année de la date (nombre entier)
    • month : mois de la date (nombre entier, de 1 à 12)
    • day : jour de la date (nombre entier, de 1 à 28, 29, 30 ou 31 selon le mois et l’année)
    • week : semaine de la date (nombre entier, de 1 à 52)
    • weekday : jour de la semaine de la date (nombre entier, de 0 à 6 – 0: lundi, 1: mardi, 2: mercredi, 3: jeudi, 4: vendredi, 5: samedi, 6: dimanche)
    • isoweekday : jour de la semaine de la date (nombre entier, de 1 à 7 – 1: lundi, 2: mardi, 3: mercredi, 4: jeudi, 5: vendredi, 6: samedi, 7: dimanche)
    • quarter : trimestre de la date (nombre entier, de 1 à 4).

    Les champs et méthodes du type « date-heure » disponibles sont :

    • ceux du type « date », et :
    • isoformat : date-heure (chaîne de caractères, format ISO 8601)
    • date : date dans la valeur « date-heure » (chaîne de caractères, format “dd/mm/YYYY”)
    • time : heure dans la valeur « date-heure » (chaîne de caractères, format “HH:MM:SS”)
    • hour : heures dans la valeur « date-heure » (nombre entier, de 0 à 23)
    • minute : minutes dans la valeur « date-heure » (nombre entier, de 0 à 59)
    • second : secondes dans la valeur « date-heure » (nombre entier, de 0 à 59)

    Accès direct à un objet « Application »

    L’accès direct à un objet « Application » d’ id {id_de_l'application} est réalisé via l’URL /wikisi/api/application/{id_de_l'application}/.

    GET /wikisi/api/application/{id_de_l’application}/

    Demande l’objet « Application » dont l’ id a pour valeur id_de_l'application. Sans paramètre fields précisé, tous les champs de l’objet sont demandés.

    Paramètre

    • fields = nom_champ1,...,nom_champN : Liste des champs demandés (noms séparés par des virgules).
      => L’ordre des champs choisi est celui utilisé dans le résultat pour présenter leurs valeurs.

    Résultat

    {

    "application" : Objet,
    => Objet « Application » demandé (restreint aux champs demandés et à leurs valeurs).

    "errors" : Objet,
    => Dictionnaire des erreurs générées lors du traitement de la requête, regroupées par thématique ou ID d’objet « Application ». Si ce champ est présent, le champ "application" ne l’est pas.

    "warnings" : Objet
    => Dictionnaire des avertissements générés lors du traitement de la requête, regroupés par thématique ou ID d’objet « Application ».

    }

    5. Requêtes sur les objets « Donnée »
    5.1 Lecture des objets « Donnée »

    Les objets « Donnée » (schéma JSON) sont accessibles via l’URL /wikisi/api/donnee/. Les paramètres fields, sort, unite, offset, limit et les restrictions sur les champs permettent de sélectionner les objets, définir l’ordre dans lequel ils doivent être retournés, et préciser les champs demandés.

    GET /wikisi/api/donnee/

    Demande une liste d’objets « Donnée ». Par défaut, sans paramètre précisé, tous les objets « Donnée » contenus dans la base de connaissance et tous leurs champs sont demandés (coûteux !).

    Paramètres

    Les paramètres et leurs valeurs sont transmis de façon standard dans l’URL: /wikisi/api/donnee/?param1=val1&param2=val2&...&paramN=valN :

    • fields = nom_champ1,...,nom_champN : liste des champs dont on demande la valeur (chaîne de caractères, noms séparés par des virgules).
      => L’ordre des champs choisi est celui utilisé dans le résultat pour présenter leurs valeurs.
    • sort = nom_champ1,...,nom_champN : liste des champs sur lesquels trier le résultat (chaîne de caractères, noms séparés par des virgules).
      => Sans paramètre sort précisé, les objets « Donnée » sont triés sur leur nom par ordre alphabétique (tri ascendant).
      => L’ordre descendant sur un champ est spécifié en faisant précéder le nom du champ du signe « – ».
    • unite = nom_de_structure : nom de structure d’une l’unité (chaîne de caractères).
      => Les objets « Donnée » retournés auront cette unité ou l’une de ses composantes comme acteur.
    • offset = valeur_offset : offset de la page (nombre entier, à partir de 0).
    • limit = valeur_limit : nombre d’objets maximum (souhaité) dans la page (nombre entier).
      => La valeur maximale de limit est 100. En cas de valeur spécifiée supérieure, la valeur 100 est retenue et un avertissement de thématique “paramètres” est généré.
    • {nom_de_champ} = valeur_du_champ : critère de sélection des objets demandés portant sur la valeur du champ {nom_de_champ}.
      => Les critères de sélection précisent les conditions que doivent vérifier les objets demandés. Autant de critères de sélection que nécessaire peuvent être cumulées au sein d’une même requête.
      => valeur_du_champ peut valoir l’une des valeurs spéciales $null ou $notNull. Ces valeurs spéciales permettent de sélectionner les objets pour lesquels le champ est vide, ou non.
      => valeur_du_champ peut être précédée d’une déclaration d’ opérateur de comparaison qui va alors se substituer à l’opérateur « égal à » utilisé par défaut. Les opérateurs de comparaison disponibles sont:
      • $eq_ci : « égal à » insensible à la casse. $eq_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $neq : « différent de ». $neq est utilisable avec les champs de tout type.
      • $neq_ci : « différent de » insensible à la casse. $neq_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $in : « inclus dans ». valeur_du_champ doit être une liste de valeurs séparées par des virgules. $in est utilisable avec les champs de tout type.
      • $in_ci : « inclus dans » insensible à la casse. valeur_du_champ doit être une liste de valeurs séparées par des virgules. $in_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $notIn : « non inclus dans ». valeur_du_champ doit être une liste de valeurs séparées par des virgules. $notIn est utilisable avec les champs de tout type.
      • $notIn_ci : « non inclus dans » insensible à la casse. valeur_du_champ doit être une liste de valeurs séparées par des virgules. $notIn_ci est adapté aux champs de type Chaîne de caractères, mais est utilisable avec les champs de tout type.
      • $gt : « plus grand que ». $gt est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $gte : « plus grand ou égal à ». $gte est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $lt : « plus petit que ». $lt est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $lte : « plus petit ou égal à ». $lte est utilisable avec les champs de type nombre entier, nombre flottant, date et date-heure.
      • $contains : « contient » (sensible à la casse). $contains est utilisable avec les champs de type Chaîne de caractères.
      • $contains_ci : « contient » insensible à la casse. $contains_ci est utilisable avec les champs de type Chaîne de caractères.
      • $startsWith : « commence par » (sensible à la casse). $startsWith est utilisable avec les champs de type Chaîne de caractères.
      • $startsWith_ci : « commence par » insensible à la casse. $startsWith_ci est utilisable avec les champs de type Chaîne de caractères.
      • $endsWith : « finit par » (sensible à la casse). $endsWith est utilisable avec les champs de type Chaîne de caractères.
      • $endsWith_ci : « finit par » insensible à la casse. $endsWith_ci est utilisable avec les champs de type Chaîne de caractères.
      • $regex : « Recherche par expression régulière » (sensible à la casse). La syntaxe d’expression régulière est celle de PostgreSQL. $regex est utilisable avec les champs de type Chaîne de caractères.
      • $regex_ci : « Recherche par expression régulière » insensible à la casse. La syntaxe d’expression régulière est celle de PostgreSQL. $regex_ci est utilisable avec les champs de type Chaîne de caractères.

    Résultat

    {

    "donnees" : liste d’objets,
    => Objets « Donnée » satisfaisant à la requête (restreints aux champs demandés et à leurs valeurs).

    "total_count" : nombre entier,
    => Nombre total d’objets dans le résultat de la requête.

    "offset" : nombre entier,
    => Offset de la page.

    "limit" : nombre entier,
    => Nombre maximum d’objets dans la page.

    "errors" : objet,
    => Dictionnaire des erreurs générées lors du traitement de la requête, regroupées par thématique ou ID d’objet « Donnée ». Si ce champ est présent, les champs "donnees", "total_count", "offset" et "limit" ne le sont pas.

    "warnings" : objet
    => Dictionnaire des avertissements générés lors du traitement de la requête, regroupés par thématique ou ID d’objet « Donnée ».

    }

    Utilisation des champs et méthodes des types « date » et « date-heure »

    La référence dans les paramètres fields et sort, et dans les critères de sélection, à des champs ou méthodes des types « date » et « date-heure » est possible en utilisant l’opérateur « . ».

    Exemple:

    • premiereDisponibilite.year=$in 2020,2021 : sélectionne les données disponibles à partir de 2020 et 2021.

    Les champs et méthodes du type « date » disponibles sont :

    • year : année de la date (nombre entier)
    • month : mois de la date (nombre entier, de 1 à 12)
    • day : jour de la date (nombre entier, de 1 à 28, 29, 30 ou 31 selon le mois et l’année)
    • week : semaine de la date (nombre entier, de 1 à 52)
    • weekday : jour de la semaine de la date (nombre entier, de 0 à 6 – 0: lundi, 1: mardi, 2: mercredi, 3: jeudi, 4: vendredi, 5: samedi, 6: dimanche)
    • isoweekday : jour de la semaine de la date (nombre entier, de 1 à 7 – 1: lundi, 2: mardi, 3: mercredi, 4: jeudi, 5: vendredi, 6: samedi, 7: dimanche)
    • quarter : trimestre de la date (nombre entier, de 1 à 4).

    Les champs et méthodes du type « date-heure » disponibles sont :

    • ceux du type « date », et :
    • isoformat : date-heure (chaîne de caractères, format ISO 8601)
    • date : date dans la valeur « date-heure » (chaîne de caractères, format “dd/mm/YYYY”)
    • time : heure dans la valeur « date-heure » (chaîne de caractères, format “HH:MM:SS”)
    • hour : heures dans la valeur « date-heure » (nombre entier, de 0 à 23)
    • minute : minutes dans la valeur « date-heure » (nombre entier, de 0 à 59)
    • second : secondes dans la valeur « date-heure » (nombre entier, de 0 à 59)

    5.3 Modification d’objet « Donnée »

    La modification d’objet « Donnée » est réalisée par requête de type PUT sur l’URL /wikisi/api/donnee/{id_de_la_donnée}/.

    PUT /wikisi/api/donnee/{id_de_la_donnée}/

    Demande la modification de l’objet « Donnée » dont l’ id est {id_de_la_donnée}. La nouvelle valeur est transmise dans le corps de la requête.

    Pas de paramètre

    Corps de la requête

    {

    "donnee" : Objet
    => Champs et leurs nouvelles valeurs. Tous les champs non précisés sont ignorés.

    }

    Résultat

    {

    "donnee" : Objet,
    => Champs modifiés et leurs nouvelles valeurs dans l’objet.

    "errors" : Objet,
    => Dictionnaire des erreurs générées lors du traitement de la requête. Si ce champ est présent, le champ "donnee" ne l’est pas.

    "warnings" : Objet
    => Dictionnaire des avertissements générés lors du traitement de la requête.

    }

    Les champs id, nom, typeCollection_id, statutSI_id, domainesSousDomaines, urba_carto et contacts doivent obligatoirement être valorisés dans les objets « Donnée ». Toute tentative de leur affecter la valeur null (ou « liste vide » pour les champs de type Collection) génère un message d’erreur et entraîne l’échec de la requête.

    5.4 Suppression d’objet « Donnée »

    La suppression d’objet « Donnée » est réalisée par requête de type DELETE sur l’URL /wikisi/api/donnee/{id_de_la_donnée}/.

    DELETE /wikisi/api/donnee/{id_de_la_donnée}/

    Demande la suppression de l’objet « Donnée » dont l’ id est {id_de_la_donnée}.

    Pas de paramètre

    Résultat

    {

    "errors" : Objet,
    => Dictionnaire des erreurs générées lors du traitement de la requête.

    "warnings" : Objet
    => Dictionnaire des avertissements générés lors du traitement de la requête.

    }

    Exemple de requête:

    DELETE /wikisi/api/application/493/
    => demande de suppression de l’objet « Donnée » id=493.
    retourne:
    HTTP 204 NO CONTENT
